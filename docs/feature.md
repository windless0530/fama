# Fama · 产品目标与功能规格

> 一句话：跨端（iOS / Windows / macOS）原生 App——多 Tab 内嵌各家 AI 的官方网页版，配一个统一输入框：**一次输入，同时发到所有站点**，不再重复打字或粘贴四次。
>
> 本版（webview 聚合壳）取代最初设想的「API 并发问答网站」方案，决策过程见文末「演进与决策记录」。

## 1. 项目概述

个人自用的 AI 聚合客户端。用系统 webview 内嵌 ChatGPT / GLM / DeepSeek / Kimi 的网页版，直接在各自页面内以官方原生方式登录、消耗各自的（免费）网页额度；App 在此之上提供核心增值：**统一输入、一次多发**。

核心设计原则：

- **不做协议层逆向**：与站点的交互止步于「正常用户在页面内操作」（DOM 脚本注入），不碰网络层；
- **站点改版影响面最小**：每站点一个小的注入脚本，改版只维护对应脚本；
- **新增一个 AI 站点 = 一条 Tab 配置 + 一个注入脚本**，不改核心代码。

## 2. 核心功能

### 2.1 多 Tab 内嵌 AI 网页

- 首批站点：ChatGPT（chatgpt.com）、GLM（chatglm.cn）、DeepSeek（chat.deepseek.com）、Kimi（kimi.com）；
- 各 Tab 使用独立 cookie 容器：同一家可并行登录不同账号，互不干扰；
- 登录/登出/会话历史直接使用各家网页自带能力，App 不接管、不存储任何站点凭据；
- 桌面端可选「分栏/网格」布局，多站点回答并排对照；移动端为单 Tab + 底部切换。

### 2.2 统一输入 · 一次多发（核心价值）

- App 常驻统一输入框：发送后，把问题自动填入所选各站的输入框并触发发送；
- 可勾选本轮要发送的站点子集（默认全部已登录站点）；
- 实现方式为页面内脚本注入（定位输入框 → 模拟输入 → 触发发送按钮），不涉及流量解析；
- 降级策略：某站注入失败时，该 Tab 自动获得焦点、问题自动复制到剪贴板，一键手动粘贴；
- 两种发送模式：「自动发送」与「仅填充、逐站手动确认发送」。

### 2.3 本地轻量记录（不含回答内容）

- 本地数据库记录每一轮：问题原文、时间、发送到哪些站点；
- 可对「某轮 × 某站点」的回答点赞 👍 / 踩 👎（用户主观评价，不抓取回答正文）；
- 支持按时间浏览历史轮次（未来的搜索功能基于这份本地日志）；
- 数据仅存本地设备，无后台服务器。

### 2.4 跨端与分发

- **iOS 优先**开发与使用：个人开发者账号（$99/年）+ TestFlight 自用分发（构建每 90 天需重新上传）；
- Windows / macOS 桌面端随后跟进，与 iOS 共享同一代码库；
- 三端均使用系统 webview（iOS: WebKit / Windows: WebView2 / macOS: WebKit），页面渲染无兼容性问题。

## 3. 非目标（明确不做）

- 抓包 / 流量解析 / 回答正文抓取——脆弱、违反条款、维护成本高（已否决，见文末决策记录）；
- API 接入与 provider 适配层（v1 方案；若未来想加「API 统一问答页」，可在本 App 内作为二期能力重启，架构上不冲突）；
- 多用户、云同步、后台服务器；
- 通用浏览器功能（书签、扩展、任意站点标签管理）——只服务这几个固定 AI 站点。

## 4. 关键约束与风险

- 与站点的交互止步于 DOM 注入：该级别自动化接近「浏览器插件填表」，风险远低于协议层逆向，但不为零；保守场景可切换「仅填充」模式；
- 站点改版可能使注入脚本失效：影响范围仅该站脚本，且有降级策略兜底；
- 若未来送审 App Store，以「带统一输入的聚合工具」定位规避纯壳 4.2（最低功能性）风险；TestFlight 自用无此问题。

## 5. 演进与决策记录（为什么是这个方案）

| 方案 | 结论 | 原因 |
|---|---|---|
| API 并发问答网站（v1，已归档） | 搁置 | 稳定可行，但 ChatGPT 无免费 API 通道，免费网页额度与 API 额度不互通；GLM/DeepSeek/Kimi 三家可零成本跑通 |
| OAuth 复用网页版账号 | 不可行 | 各家官方均未提供此类通道；OAuth 发放的是 API 令牌，与网页额度是两套体系 |
| 网页内嵌（iframe） | 不可行 | 各站点 X-Frame-Options / CSP frame-ancestors 禁止被第三方网页嵌入 |
| 无头浏览器自动化 / 抓包解析 | 否决 | 逆向私有协议：脆弱、违反条款、有封号风险、每家每平台一套方案 |
| **webview 内嵌 + DOM 注入（本方案）** | **采用** | 唯一能「零 API 费用 + 用网页版额度 + 跨端原生」的稳态路径 |
